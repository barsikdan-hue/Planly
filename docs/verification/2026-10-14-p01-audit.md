## Auth and security gaps

1. `auth/owner.ts::authenticateOwner` lines50–54 accepts one env email/hash; `ensureOwner` bootstraps its existing row and disconnected accounts. `auth/session.ts::createOwnerSession/getOwnerBySessionToken` lines30–59 reject non-owner email. users schema46–52 lacks roles/password/status; auth.integration54–61 explicitly requires rejecting a second user. Root of unavailable colleague login is CODE PROVEN, intended single-owner behavior.
2. `scheduler/processor.ts::readPublication`16–28 joins by scalar IDs. It omits equal owners, target.postId matching publication.postId and matching provider. `processPublication`101–111 derives text and destination from that graph. Scalar FKs permit mismatched rows. Ordinary create/update validates ownership; no production incident/leak is proven. Add RED fixture before any fix.
3. `posts.ts::readOwnedPost`61–64 reads post_media IDs without media owner join. A malformed cross-owner link can expose the ID, not a signed URL. Worker's existing media query filters ownership but can omit inconsistent attachments instead of rejecting the graph.
4. `social-accounts.ts::connectSocialAccount`89–94 and connector registry23–25 use shared TG/MAX env tokens. Bot posting permissions are validated; the code does not prove that a logged-in colleague owns the proposed destination. Never unlock current connect routes for new users before separate destination-authorization design.
5. Shared Library is not implemented: library_items.userId/status and global posts.source_library_item_id unique index admit one current conversion. Removing owner filters would break both privacy and independent opt-in. Preserve this until separate shared-source/user-copy design.
6. Private preview query `media.ts::listMediaAssetsWithPreview`33–44 scopes rows before signing; keys contain hashed user prefix. Signed URLs last300s; existing URL not revoked by logout. No R2 permission/configuration proof obtained.
7. Auth cookie is httpOnly/secure-in-production/SameSite=lax, opaque random token with stored HMAC, seven-day expiry. Token deletion exists; user suspension/revoke-all/account recovery do not. Core HTTP helper lacks explicit no-store and uniform CSRF checks; scheduling/analytics have custom guards, Swipe private no-store, VK has optional Origin check. Cross-origin exploitability is not tested/proven by this audit. Multiuser auth must validate these boundaries with real sessions before release.
8. Telegram analytics ingestion explicitly requires OWNER_EMAIL (`analytics/telegram.ts:27–34`). MAX refresh uses common env token. Instagram has no provider enum/connector. P01 does not claim multiuser analytics/four-network capability.
