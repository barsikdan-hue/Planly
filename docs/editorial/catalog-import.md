# Повторяемый импорт редакционного каталога

Внешний `realty-editorial-v3` готовит и проверяет материалы. Этот runner проверяет
структуру/байты и импортирует готовое через существующие API; он не пишет тексты,
не повторяет редакционную приёмку и не публикует в соцсети.

## Пакет

В папке выпуска лежит JSON с `period: YYYY-MM`, `items` (1–200), уникальными
`id`, `title` до200символов, `text:{path,sha256}` и `media:[{path,sha256}]`.
Пути относительны папке manifest, без выхода/симлинков наружу. Текст1–20000символов;
до20media на материал; общий пакет до100MiB. Крупный выпуск делить на отдельно
зафиксированные пакеты. Каждый файл проходит SHA256 и существующий media validator.

Готовый пример из уже проверенных L01–L03:

```powershell
node --experimental-strip-types scripts/import-catalog.mjs --manifest docs/editorial/lentaro-m1-2026-10-19/catalog-import.json
```

Без `--apply` только offline-проверка: сеть, DB, uploads и provider sends0.
Исходные утверждённые материалы и их bundle manifest не изменяются.

## Разрешённый импорт

После выпуска совместимого source и согласования целевого runtime:

```powershell
node --experimental-strip-types scripts/import-catalog.mjs --manifest PATH --apply --base https://stage.lentaro.ru --journal PRIVATE_ABSOLUTE_JOURNAL_PATH
```

Действующая ADMIN-сессия поступает только через process env `PLANLY_ADMIN_SESSION`,
не через аргументы, Git, чат или отчёт. Без неё live import не запускается.
Журнал держать вне Git в закрытой папке; он содержит технические receipt IDs, но
никогда session token, тексты или bytes. Параллельный импорт одного журнала запрещён.
Не передавать Cookie на redirect; смена origin, actor или package hash отвергается.

Порядок: проверить ADMIN → загрузить media → создать Library по постоянному
idempotency-key → включить shared Library. Post/scheduler/provider endpoints
не вызываются. Завершённые строки повторно не импортируются и не возвращают
самостоятельно снятый с публикации материал. Архивы пользователей не изменяются.

## Ошибки

- Неизвестный результат media upload сохраняется как PENDING. Повторный upload
  заблокирован: требуется разрешённый readback конкретного объекта/receipt.
  Не стирать журнал и не запускать новый, чтобы обойти неопределённый результат.
- Неизвестный результат Library create повторяется только с тем же сохранённым
  idempotency-key и тем же payload — через существующий durable receipt.
- Ошибка shared toggle оставляет Library ID в журнале; повтор меняет тот же owned
  source, а не создаёт ещё один. Ошибка API не становится успешным импортом.
- После падения процесса сохранённый `.lock` требует проверки владельца операции;
  runner не удаляет чужой/неопределённый lock автоматически.

Журнал является локальной картой выполнения, не backup. Для нового месяца
подготовить новую проверенную ревизию и отдельный журнал. Runtime/media/публикации
после импорта проверяются отдельно; dry-run не доказывает live acceptance.
