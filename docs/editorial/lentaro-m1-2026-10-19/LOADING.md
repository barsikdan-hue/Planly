Схемы read-only проверены в `work/Planly-lentaro-m1` на source HEAD `6cf369bff8b284f8b3c166ce2dfa531e9f449ea0`. Загрузка не выполнялась. Для трёх материалов достаточно существующих операций, новый batch importer не требуется.

2. Для L01 выбрать `assets/final/L01-r1-portrait.jpg`, сверить SHA из manifest. Штатный `POST /api/media`: multipart поле `file`. Сохранить request state до вызова, затем подтверждённый `id`, originalName, bytes и результат. **У upload нет durable idempotency key.** При таймауте/потере ответа записать `UPLOAD_OUTCOME_UNKNOWN` и остановить этот материал. Новый upload автоматически не делать. Сверить собственные медиа через существующий UI/`GET /api/media`; одно совпадение имени не доказывает совпадения байтов. При необходимости проверить signed preview тем же файловым SHA и связать найденный собственный mediaId с этой попыткой. Если однозначно сверить нельзя — оставить UNKNOWN; соседние материалы могут продолжаться.
3. Подставить только подтверждённый mediaId в `api-package.json` → `library_create.body.mediaIds` для L01. Штатный `POST /api/library-items`, JSON `{title,text,mediaIds}` и **существующий фиксированный** `Idempotency-Key` из пакета. Текст брать целиком из `materials/L01-r1.txt`; meta/provenance поля sidecar не входят в схему API. Сохранить подтверждённый libraryItemId/updatedAt в receipt. При неизвестном исходе разрешено восстанавливать с прежним ключом и точно тем же canonical payload; новый ключ или изменённый текст не являются retry.
4. Только после подтверждения созданной личной заготовки — штатная ADMIN операция `POST /api/admin/shared-library/{libraryItemId}` с `{shared:true}`. Нужны полномочия ADMIN; key библиотеки не предоставляет эти полномочия. Подтвердить появление в существующей общей библиотеке, не изменять оригинальный текст ради ускорения загрузки. Эта операция открывает материал пользователям каталога и требует разрешения на конкретную среду. Не путать с публикацией в Telegram/MAX.

Точный namespace идентичности: `batch_id + material_id + revision + snapshot_sha256 + owner/environment`. UUID creation key сохраняется при retry одной операции; другой owner/environment требует явно отдельного журнала, а не ложного reuse уже созданного результата.

Ограничение текущей штатной схемы: library API принимает только title/text/mediaIds; source IDs, полный QA, права и версии не имеют отдельного нативного поля. Поэтому полный sidecar обязателен, а journal связывает его с реальными ID. Сам статус READY в библиотеке не удостоверяет редакционный допуск. В публикуемом тексте уже остаются существенные условия, источник L03 и происхождение изображений.

Ни URL окружения, ни cookie/token, ни реальные library/media IDs не предполагались и не сохранялись заранее. Имеющийся template — план, не receipt успешной загрузки.
